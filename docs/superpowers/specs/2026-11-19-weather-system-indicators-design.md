## 目标与范围

在现有小岛加入天气功能，将当前合并的 CPU / MEM 状态拆成独立配置项。用户已确认本阶段范围为天气与 CPU / 内存独立开关。计时器、番茄钟、录音速记、多天气源、分钟级降水和气象预警不在本阶段范围内。此前 Ctrl 拖动问题保留为独立待排查事项。

沿用项目现有紧凑布局、主题 token、lucide 图标和中英双语，不复制参考图片的宣传页布局。

## 方案选择

1. 推荐：天气作为小岛内置模块，CPU 和内存作为独立状态项。复用现有设置、收起排列和展开页面体系，入口与其他功能一致。
2. 天气放独立窗口：便于展示更大卡片，但查看时脱离小岛，增加窗口生命周期和权限维护。
3. 通过插件实现天气：适合后续多源扩展，但会增加插件安装与运行依赖，不适合本次开箱使用目标。

采用方案 1。天气网络请求走 Rust 的固定 HTTPS 服务端点，前端通过类型化命令调用；复用已有 reqwest，不引入新网络依赖。

## 天气交互

- 设置增加独立天气入口，提供启用开关、城市搜索与当前城市。默认关闭；开启但尚未选城市时显示选择城市的入口，不虚构天气读数。
- 第一版手动搜索城市，不自动读取位置或按 IP 推断位置。搜索结果展示名称、行政区和国家，明确区分同名城市。
- 使用 Open-Meteo 免费公共接口，无需用户填写 Key；设置标注 Open-Meteo 数据来源。
- 收起态增加可排序的天气项，显示图标、城市和温度；点击展开天气页。城市长名称截断，完整名称在提示和展开页展示。
- 展开页显示城市、当前温度、天气、体感、湿度、风速和接下来六个小时的天气与温度，提供刷新和城市设置入口。
- 加载、未选城市、请求失败和过期缓存有各自的双语状态。刷新失败保留上次成功结果并标注更新时间；无缓存时显示重试入口。
- 天气页加入现有页面入口及排序，不改变现有窗口 label 和入口参数。

## 数据与请求

- 城市搜索使用 Open-Meteo geocoding 接口，搜索词限长并进行 URL 参数编码；输入防抖、最小长度限制，忽略过时响应。
- 预报仅访问 Open-Meteo forecast 固定域名，校验经纬度及响应字段，设置请求超时；错误不包含无关内部实现信息。
- 请求当前天气以及 hourly 温度、天气码，使用摄氏度和 km/h；请求自动时区，前端按预报地点时区显示小时，避免按用户电脑时区错位。
- 启用并选定城市后立即获取，成功结果缓存 15 分钟，之后刷新。请求防重入；切换城市后旧请求不能覆盖新城市数据。
- 关闭天气后停止定时请求；手动刷新有短间隔限制，失败不进行密集重试。城市搜索仅在用户搜索时触发。
- 配置和缓存继续使用 localStorage；设置包含选定城市的稳定标识、名称、行政区、国家、经纬度与时区。缓存包含城市标识、获取时间和校验后的天气数据；旧城市缓存不能用于新城市。
- 新命令、事件或存储键在实现时同步登记 contracts.md，存储位置同步 data-storage.md。不增加用户数据库或云同步。

## CPU 与内存

- 设置中呈现两个明确独立的开关：“CPU 使用率”和“内存使用率”，可分别启用；各自拥有独立排列项。
- 保留当前 get_system_status 返回结构，避免破坏已添加的命令契约。任一指标开启且收起显示时沿用两秒采样，两项均关闭时停止轮询。
- CPU 首次采样显示 `CPU --%`，内存在有效采样前显示 `MEM --%`，不显示虚假的零占用。
- 旧排列中的 system 项迁移为相邻 cpu、memory 两项，保持原位置和其他项的相对顺序。旧配置缺少开关时两项均开启，以保留原有可见行为；新天气默认关闭。
- 既有窄岛规则继续避免挤占待办计时器；隐藏状态项不改变保存的排序，设置里说明窄岛可能自动隐藏。
- CPU 与内存是状态展示，无需假装成可点击的功能按钮；用户所说“单独选项按钮”落实为设置中的独立开关和排列中的独立项。

## 代码组织与验证

- 天气领域集中在 src/features/weather/，原生请求集中在 src-tauri/src/weather/；窗口层只组合与接线。更新就近 AGENTS.md 和架构地图。
- UI 约定补充 docs/design/ 中对应区域文档，避免把计划当作已实现功能写入现有规则。
- 单测覆盖旧 system 排列迁移、独立开关、天气码、天气响应校验、时区小时筛选和缓存有效性；回归页覆盖天气主要状态、点击展开、独立开关及窄岛布局。
- 实现后运行 pnpm check、pnpm build、pnpm test:regression、cargo test --manifest-path src-tauri/Cargo.toml、pnpm tauri build --no-bundle。Rust 全量测试前按 CI 构建 example-hello 夹具到同一 target。
- 不生成安装包、不部署、不推送。按可验证功能单元提交，完成后归档真实验证结果；真实天气联网和桌面交互验收与 mock 回归结论分开报告。

## 待用户审阅的具体约定

本设计明确第一版使用手动选城市、单一免 Key 数据源；CPU 和内存独立选项指设置开关与排列项。确认文档后进入实施计划与代码实现。
