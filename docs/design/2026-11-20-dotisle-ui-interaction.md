## 范围与选择

用户已选择“先做 UI 与交互：显示分层、音乐卡片、统一提醒队列”。本期包含收起态活动分层、展开音乐页和现有提醒的协调，不接入新数据来源。

比较三种实现路径：仅改样式成本最低，但无法解决同时到达的提醒互相覆盖；沿用现有 React/Tauri 能力统一展示策略，可以兼顾外观与提醒生命周期；完整复刻 DotIsle 控制中心涉及新窗口和桌面组件，超出本期。采用第二种。

参考仓库使用 main 快照 d09a751a2fcc337b03ae09860052f9b1317f1250。借鉴信息层级、封面氛围与活动调度，不移植其原生渲染架构、微信数据读取方式或历史主题资源。

## 一、显示分层

收起态只突出一个主要活动，完整内容在已有展开页显示：

1. Agent 等待确认及额度告警沿用当前专门流程，优先于普通活动；本期不把确认操作改成自动轮播。
2. 临时通知展示正文或短状态，结束后恢复当时仍有效的活动，而不是缓存旧歌词或旧计时。
3. 音乐播放时歌词独立居中，不受普通“文字”开关影响。岛仔固定最左侧；未读消息入口和正在运行的待办计时保留，天气、CPU、内存、时钟及文件计数让位。
4. 无歌词活动时，运行中的待办计时优先于品牌与空闲统计；显示简短任务和完整倒计时，长任务名称让位于计时。
5. 空闲时恢复用户已启用、已排序的普通指标。保留所有现有开关、排序与旧存档兼容。

主内容与辅助内容按同一份可见性结果计算宽度，避免“已经隐藏却仍占宽度”。宽度在既有自动/固定宽度、缩放和原生舞台边界内计算；空间不足时让任务文字与辅助指标退让，时钟数字和计时不得压成省略号。

点击歌词/音乐入口进入音乐页，点击任务进入待办；消息来源图标仅有未读时显示并沿用直接打开客户端行为。Agent 收起仅显示图标和简短阶段，完整回复留在展开页。

## 二、展开音乐页

保持“岛体就是播放器”的已有约定：不新增嵌套卡片、边框或另一套不透明底色。

- 以现有歌曲封面生成低对比的模糊氛围层，限于音乐内容区域，使用遮罩和主题语义色保证歌词可读；全局经典、液态玻璃、磨砂玻璃仍由现有岛体材质承担。切离音乐页即卸载该图层。
- 结构为歌曲信息、歌词、进度、播放控制。歌词存在时缩小封面，当前句最突出，上下句与译文弱化；无歌词时封面和歌曲信息占用释放的空间。
- 播放/暂停为最明确的主操作，上下曲为次操作，歌词设置与兼容性提示保持独立入口。长歌名不挤占操作按钮。
- 保留无封面、无歌词、未知时长、暂停、控制失败和空闲状态的现有真实含义。没有时间线时不伪造可拖动进度，也不改变逐字填充默认关闭等已确认偏好。
- 复用现有封面取色与图片，不新增网络图片请求、图标库或字体。减少动态效果时停止新增氛围动效；暂停时弱化动效。

## 三、统一提醒队列

### 输入与边界

在窗口组合层增加统一调度，将当前 QQ、微信、邮箱、办公消息、插件预览以及设备变化转换为内部提醒记录。保留现有功能模块负责接收、读取、复制、打开客户端等能力；不更改外部事件、命令和存储格式。

Agent 确认、额度提醒和用户打开的面板作为调度边界处理，仍由原有逻辑拥有交互与尺寸。普通队列不覆盖正在操作的面板。

现有来源的短时 preview 不能继续独立决定排队内容是否到期：调度接纳时保存该次提醒快照，展示倒计时从实际开始展示时计算。正文加载完成可更新同一条提醒，不重新入队。

### 排序与去重

- 普通队列内验证码优先于聊天/邮件/插件正文，正文优先于设备状态。验证码只是提高展示优先级，不自动复制，继续遵守现有自动复制开关。
- 同优先级按到达顺序展示。新的高优先级提醒可以接替低优先级提醒，但鼠标悬停、选中文字或复制操作期间不替换正在阅读的内容，待释放后再切换。
- 被接替的普通消息保留剩余展示时长；设备提示被接替即丢弃，不在稍后补弹旧锁定状态。
- 使用来源、稳定消息标识和接收时间识别重复；轮询重复快照和正文加载变化不重新计数或刷新停留时间。缺少原生消息ID时，在该来源内使用接收时间及内容摘要区分。
- 队列最多20条待展示项。普通正文等待超过60秒丢弃，验证码等待超过30秒丢弃；这是展示时效，不声称验证码已经失效。容量不足时优先淘汰最旧低优先级项。
- 同一设备的连续变化合并为最新状态，设备提示仍只显示约2秒；高优先级内容、展开态或游戏屏蔽期间继续建立设备基线，不补弹旧变化。

### 生命周期与恢复

- 正文停留时长沿用当前设置；悬停或选中暂停展示倒计时，移出且无选区后继续。设备提示沿用短暂状态提示规则，不变成长期占位。
- 来源关闭、内容被清空或已读操作使该条提醒失效时，移除对应待展示内容。来源列表与未读图标仍由各自真实状态驱动。
- 用户展开主面板、托盘隐藏或进入禁止提醒的游戏状态时清理普通待展示队列，避免回来后补弹积压消息。恢复时从最新事件继续。
- 游戏允许提醒时沿用独立时长、点击穿透与不抢焦点策略，不启用悬停保持。
- 队列结束后用当前媒体、计时和Agent状态重新推导收起内容。尺寸、材质、悬停保持及贴边露出状态同步更新，避免透明命中区残留或岛体提前缩回。

## 实现落点与兼容

- `features/media/`：音乐页和封面氛围样式，复用已有取色、歌词与进度组件。
- `windows/island/`：主要活动推导、提醒调度接线与可见宽度结果；较大的纯队列状态机拆到职责明确的独立模块，不扩大接近行数上限的 IslandApp。
- `features/messages/`、`features/device-notices/`：仅为统一生命周期提供必要的事件标识、快照更新和关闭信号，保持领域能力归属。
- 本期原则上不新增持久化设置；队列只存内存。涉及共享类型时同步更新回归mock；所有新增用户文案中英双语。
- 完成后将已实施行为回写 `docs/design/island.md`、`music.md`、`notifications.md`，对外契约确有变化时才更新 contracts。

## 验收与验证

先增加有意义的失败测试，再实现状态和样式：

- 队列：同时到达、优先级、FIFO、重复轮询、正文更新、暂停与剩余时间、过期与容量、设备合并、来源失效、游戏/展开边界及卸载清理。
- 收起态：文字关闭仍显示歌词，音乐与待办计时并存，Agent长回复不入收起栏，恢复时读当前状态，指标切换与自动宽度一致，窄岛计时/时间不截断。
- 音乐页：有/无封面及歌词、长标题、未知时间线、暂停与失败、键盘操作、浅深主题、三种材质及减少动态效果；覆盖90%与120%字号和既有缩放边界。
- 消息：悬停、选字、点击复制不触发打开或拖动；同来源多条和跨来源连续提醒；侧栏命中范围和材质保持。

前端必须运行 `pnpm check`、`pnpm build`、完整 `pnpm test:regression`。如实现涉及原生窗口、IPC或Rust改动，补跑 `cargo test --manifest-path src-tauri/Cargo.toml` 与 `pnpm tauri build --no-bundle`。最终提供新可执行文件时运行无安装包构建；不生成安装包或推送远端。真实播放器和桌面消息未手动验证的部分单独列出，不以浏览器mock结果代替现场验收。
